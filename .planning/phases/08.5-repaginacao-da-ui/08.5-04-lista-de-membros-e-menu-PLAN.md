  <name>Task 2: MemberRow focável com menu de membro (clique, Enter e botão direito)</name>
  <files>src/renderer/src/components/shell/MemberList.tsx</files>
  <action>
    Converter `MemberRow` de `<div>` para `<button type="button">` (mantendo o
    layout atual: avatar + nome, `hover:bg-accent/50`, `rounded`, `w-full`,
    `text-left`). Um `<div>` com menu é inalcançável por teclado — é o defeito
    de acessibilidade clássico que o RESEARCH aponta em MemberList.tsx:118-127.

    Envolver a linha num `DropdownMenu` CONTROLADO (padrão único de menu da
    fase, decidido no Plano 08.5-02 — não usar `ContextMenu` do Radix):
    - `const [open, setOpen] = useState(false)`, `<DropdownMenu open={open} onOpenChange={setOpen}>`.
    - `<DropdownMenuTrigger asChild>` recebe o `<button>` da linha.
    - No `<button>`, `onContextMenu={(e) => { e.preventDefault(); setOpen(true) }}`
      — botão direito abre o MESMO menu. Custo aceito e registrado: o menu
      ancora na linha, não na posição do cursor.

    Itens do menu — SÓ o que existe hoje no backend (`convex/friends.ts`,
    `convex/dms.ts`):
    1. **"Copiar identificador"** — copia `${username}#${tag}` via
       `navigator.clipboard.writeText`, depois `toast.success('Identificador copiado')`;
       no catch, `toast.error(...)`. Mesmo comportamento que o painel de
       amigos já oferece para o próprio identificador.
    2. **"Adicionar amigo"** — chama `api.friends.sendFriendRequest({ username, tag })`
       (`useMutation`). Sucesso → `toast.success('Pedido de amizade enviado')`.
       Erro → `toast.error(mensagem do erro)`: a mutation já lança mensagens
       legíveis em português ("Você não pode adicionar a si mesmo", "Usuário
       não encontrado"), então repassar a mensagem é melhor que inventar uma.
       NÃO esconder o item para si mesmo nem para quem já é amigo: a query da
       lista não traz esse dado, buscar isso exigiria query nova, e o erro
       devolvido pela mutation já é claro. Registrar essa escolha em comentário.

    NÃO incluir "Enviar mensagem direta": `dms.getOrCreateDmChannel` exige
    amizade e falharia para a maioria dos membros — um item de menu que quase
    sempre dá erro é pior que a ausência dele. NÃO incluir expulsar/silenciar/
    gerenciar cargo: não existe mutation, e criar uma seria reescrever a
    autorização do backend (explicitamente fora desta fase).
  </action>
  <verify>`grep -n "<button" src/renderer/src/components/shell/MemberList.tsx` mostra a linha do membro como botão; `grep -n "DropdownMenu" ...` mostra o menu; `npm run typecheck` limpo; `npm run build` passa.</verify>
