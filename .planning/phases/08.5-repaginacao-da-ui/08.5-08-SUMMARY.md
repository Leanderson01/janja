## (c) O modelo de persistência

`src/renderer/src/lib/sidebar-preferences.ts` — terceiro módulo do projeto no mesmo molde
(`voice-preferences.ts` da 07-05, `screenshare-preferences.ts` da 08-05):

```ts
export type SidebarPreferences = { textCollapsed: boolean; voiceCollapsed: boolean }
const STORAGE_KEY = 'janja:sidebar-preferences'
export const DEFAULT_SIDEBAR_PREFERENCES = { textCollapsed: false, voiceCollapsed: false }
export function loadSidebarPreferences(): SidebarPreferences
export function saveSidebarPreferences(partial: Partial<SidebarPreferences>): SidebarPreferences
```

Três decisões que estão no código como comentário e valem repetir:

1. **É estado de MÁQUINA, não de conta — não vai para o Convex.** Recolher a seção VOZ é
   uma escolha sobre o formato desta janela, neste monitor; ela não deve viajar com a conta
   para o notebook de 13".
2. **A preferência é GLOBAL, não por servidor.** As seções derivam do campo `type` do
   canal (o modelo desta fase não tem categoria), então "TEXTO" e "VOZ" significam a mesma
   coisa em todo servidor. Um mapa `serverId -> estado` só acumularia chaves órfãs quando
   alguém saísse de um servidor.
3. **O default é tudo expandido.** Abrir o app pela primeira vez e não encontrar os canais
   que você acabou de criar seria o pior estado inicial possível.

O `save` faz **merge com o valor persistido**, não com o default — aqui já existem dois
campos, então sem o merge alternar VOZ resetaria TEXTO silenciosamente. Tem teste próprio
para isso.

No componente, `useState(loadSidebarPreferences)` (a função, não o resultado da chamada):
o storage é lido uma vez, no primeiro render, e daí em diante o estado do React é a fonte
da verdade — o storage só recebe escrita. `setSectionOpen` é o **único** lugar que traduz
o `open` do Radix para o `collapsed` do módulo.

`w-[3px]` numa de 240px com texto ao lado.

`--success` continua sendo **significado** (alguém está falando, alguém está
compartilhando), não destaque, e por isso não conta contra a regra do tom único.

## Deviations from Plan

**Nenhum desvio.** O plano foi executado como escrito, com três acréscimos pequenos que
cabem dentro do que ele já pedia:

1. **`min-w-0` explícito** nos três `truncate` de dentro do Collapsible (item 5 da Task 3
   mandava "conferir que continuam"). `flex-1` sozinho não garante encolhimento abaixo do
   conteúdo em flex — `min-width: auto` é o default. O `truncate` funcionava por sorte de
   layout; agora funciona por regra. Coluna de 240px fixos, nome de canal longo é o
   primeiro a estourar.
2. **`cn()` no anel de fala** (`cn(isSpeaking && 'ring-2 ring-success')` em vez do ternário
   com `undefined`). O plano dizia que o ternário "já é aceitável"; a forma com `cn()` é
   mais curta e coerente com o resto do arquivo.
3. **`ChannelSection` e `SelectedMarker` como componentes locais**, em vez de JSX repetido
   duas vezes em cada caso. Mesmo padrão que o arquivo já usava (`TextChannelRow`,
   `VoiceChannelRow`) e menos superfície para o 08.5-12 esbarrar.

teclado próprio que possa estar errado.

## O que NÃO foi verificado — e não podia ser

**Ambiente WSL2: sem Windows, sem tela, sem janela Electron. Nenhum pixel foi renderizado
durante esta execução. Eu não vi a sidebar recolher, não vi o chevron girar e não vi a cor
do marcador.** Tudo acima é consequência do código, do CSS gerado e dos testes de contrato

Fica para o checkpoint humano (Plano 08.5-17, com o roteiro do 08.5-15, em Windows nativo):

1. **A animação de recolher é suave e a lista não "pula".** As classes
   `animate-collapsible-up/down` existem no CSS gerado; que elas produzam movimento
   agradável depende de `--radix-collapsible-content-height`, medido em layout real, que o
   jsdom não faz.
2. **O chevron gira 90° ao abrir** e volta ao fechar.
3. **A persistência entre dois boots do app**: recolher VOZ, **fechar o app**, reabrir,
   continuar recolhido. O teste prova o contrato `load`/`save` — o observável daqui —, não
   o reinício. Item já previsto no roteiro do 08.5-15.
4. **A barra de destaque do canal selecionado é visível** contra o `bg-accent` da linha e
   não é cortada pelo `rounded-md` nem pelo `overflow-hidden` do `CollapsibleContent`.
   Ela tem 3px: se ficar imperceptível no monitor real, subir para `w-1` (o valor do rail)
   é uma linha.
5. **O badge de não lidas em `bg-highlight` é legível** — texto `--highlight-foreground`
   (quase branco) sobre o roxo-azulado do destaque, num badge de 12px.
6. **Teclado ponta a ponta:** Tab chega aos dois gatilhos de seção na ordem certa (entre o
   cabeçalho do servidor e a primeira linha de canal), Enter/Espaço alternam, e o anel de
   foco do gatilho é visível — ele não tem classe de foco própria, herda o
   `outline-ring/50` global do `@layer base`. **Se o foco do gatilho estiver invisível,
   é aqui que se descobre.**
7. **Com a seção VOZ recolhida enquanto conectado**, a `VoiceControlBar` do rodapé é
   referência suficiente (ver seção (d)) — ou não é, e aí vira decisão de UI para o humano.
