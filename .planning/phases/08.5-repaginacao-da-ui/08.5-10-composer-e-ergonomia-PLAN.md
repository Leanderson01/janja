  <name>Task 1: Guarda de IME no composer, com teste de teclado</name>
  <files>src/renderer/src/components/shell/MessageInput.tsx, src/renderer/src/components/shell/MessageInput.test.tsx</files>
  <action>
    Em `handleKeyDown`, acrescentar a guarda:
    ```tsx
    if (
      event.key === 'Enter' &&
      !event.shiftKey &&
      !event.nativeEvent.isComposing &&
      event.keyCode !== 229
    ) {
      event.preventDefault()
      submit()
    }
    ```
    `isComposing` é o sinal do próprio navegador de que uma composição está
    ativa — não existe heurística de texto que substitua isso. O
    `keyCode !== 229` é redundante no Chromium (o único runtime deste app) mas
    custa uma linha e cobre o caso conhecido de `compositionend` disparar antes
    do `keydown`; o RESEARCH marca essa parte como MEDIUM-HIGH de confiança, e
    aqui a linha extra é mais barata que a dúvida.

    Comentar acima do handler POR QUE isso existe (sem o guard, quem digita em
    japonês envia a mensagem no meio da palavra) — é a classe de código que
    alguém "simplifica" seis meses depois por não entender.

    Acrescentar também: desabilitar o botão de envio quando o conteúdo aparado
    está vazio (`disabled={content.trim().length === 0}`) — hoje o botão está
    sempre habilitado e clicá-lo com campo vazio não faz nada, o que é um
    estado morto visível.

    Criar `MessageInput.test.tsx` (`// @vitest-environment jsdom` na primeira
    linha, import de `@/test/jsdom-setup` logo depois, seguindo o padrão que o
    Plano 08.5-02 provou), cobrindo 4 casos com `fireEvent`/`userEvent`:
    1. Enter simples com texto → `onSend` chamado uma vez com o texto aparado.
    2. Shift+Enter → `onSend` NÃO chamado (e o texto continua no campo).
    3. `fireEvent.keyDown(textarea, { key: 'Enter', isComposing: true })` →
       `onSend` NÃO chamado. Este é o teste que existe por causa do IME:
       `KeyboardEvent` do jsdom aceita `isComposing` no init dict, então dá
       para simular composição sem IME real.
    4. Enter com campo vazio ou só espaços → `onSend` NÃO chamado.

    Se `fireEvent` não propagar `isComposing` para `event.nativeEvent` na
    versão instalada do testing-library, tentar construir o evento à mão
    (`new KeyboardEvent('keydown', { key: 'Enter', isComposing: true, bubbles: true })`
    + `textarea.dispatchEvent(...)`). Se nem assim for observável, NÃO fingir:
    remover o caso 3, marcar no arquivo e no SUMMARY que o guard de IME ficou
    sem prova automatizada, e adicionar o item ao roteiro do checkpoint humano
    (Plano 08.5-15) para ser testado com o IME japonês do Windows.
  </action>
  <verify>`npx vitest run src/renderer/src/components/shell/MessageInput.test.tsx` passa; `npm run typecheck` limpo; `grep -n "isComposing" src/renderer/src/components/shell/MessageInput.tsx` retorna a guarda.</verify>
