<objective>
Trocar o modelo mental da área principal: ela deixa de ser "a área de conversa"
e passa a ser um **palco que alterna entre texto e call**. Entrar numa call põe
o palco na frente; navegar para um canal de texto mostra o texto sem derrubar a
call; e existe caminho de volta.

Purpose: **decisão do usuário em 2026-08-19, depois de usar o app no Windows.**
Hoje `ConversationArea.tsx` decide o que mostrar só por `selectedChannelId` —
olhar um canal de texto enquanto se está numa call é impossível, porque
selecionar o canal de texto é a única forma de sair da tela da call, e clicar
de novo no canal de voz DESCONECTA. Isso é esqueleto de layout, não
acabamento: por isso este plano vem ANTES do polimento do composer (Plano
08.5-10), da sidebar (08.5-08) e do rodapé (08.5-09), que editam os mesmos
arquivos em ondas seguintes.
Output: `CallStage` existindo como região própria, o estado de visualização
resolvido por função pura testada, e a call sobrevivendo à navegação.
</objective>

<decisao_de_estado>
**Não entra entidade nova de estado. Entra UM booleano e uma função pura.**

O que já existe em `SelectionContext` (desde a F3): `joinedVoiceChannelId`
(intenção de estar na call) e `selectedChannelId` (o que se está olhando).
Falta exatamente uma informação que não dá para derivar das duas: quando o
usuário está numa call E selecionou um canal de texto, ele quer ver o texto —
mas quando ele volta ao canal de voz, quer ver o palco. Sem um bit próprio, o
"voltar" seria indistinguível do "estar olhando o texto".

Solução: `viewingStage: boolean` no `SelectionContext`, com transições
explícitas (Task 2), e a decisão de renderização derivada por
`resolveMainView()` (Task 1). Alternativas descartadas, para não serem
reabertas:
- **Guardar um "modo" livre ('text' | 'stage' | 'preview')** — três estados
  onde dois deles já são deriváveis de `selectedChannelId`, criando a chance
  de o modo discordar do canal selecionado.
- **Deduzir tudo de `selectedChannelId === joinedVoiceChannelId`** — não
  distingue "estou vendo o texto durante a call" de "não estou em call
  nenhuma", que é o caso inteiro deste plano.
</decisao_de_estado>

  <action>
    Criar `stage-view.ts`:
    ```ts
    export type MainView =
      | { kind: 'stage'; channelId: Id<'channels'> }      // call em que estou
      | { kind: 'text'; channelId: Id<'channels'> }       // canal de texto
      | { kind: 'voice-preview'; channelId: Id<'channels'> } // canal de voz onde NÃO estou
      | { kind: 'empty' }

    export function resolveMainView(input: {
      joinedVoiceChannelId: Id<'channels'> | null
      viewingStage: boolean
      selectedChannelId: Id<'channels'> | null
      selectedChannelType: 'text' | 'voice' | null   // null = canal ainda carregando/inexistente
    }): MainView
    ```
    Regras, nesta ordem:
    1. `joinedVoiceChannelId !== null && viewingStage` → `stage` do canal
       conectado. **O palco ganha da seleção**: é o que faz "voltar para a
       call" funcionar mesmo com um canal de texto selecionado.
    2. `selectedChannelType === 'text'` → `text`.
    3. `selectedChannelType === 'voice'` → `voice-preview` (ver quem está num
       canal de voz sem entrar; comportamento que já existe hoje e não pode
       regredir).
    4. Resto → `empty`.
    Sem `Id<>` importado do Convex se isso complicar o teste — pode ser
    genérico sobre `string`; o que importa é a regra, não o tipo nominal.

    Teste (`edge-runtime` padrão, função pura, sem DOM): tabela de verdade com
    todas as combinações relevantes, incluindo os casos que são o ponto do
    plano:
    - em call + viewingStage=true + canal de texto selecionado → `stage`
    - em call + viewingStage=false + canal de texto selecionado → `text`
      (**é a call continuando enquanto se lê o texto**)
    - em call + viewingStage=false + nenhum canal selecionado → `empty`
    - fora de call + canal de voz selecionado → `voice-preview`
    - fora de call + viewingStage=true (estado inconsistente) → NÃO devolve
      `stage` (a regra 1 exige `joinedVoiceChannelId !== null`)
  </action>
