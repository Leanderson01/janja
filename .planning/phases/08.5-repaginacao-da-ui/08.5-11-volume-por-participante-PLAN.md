  <files>src/renderer/src/lib/participant-volumes.ts, src/renderer/src/lib/participant-volumes.test.ts</files>
  <action>
    Criar `participant-volumes.ts`, no mesmo padrão defensivo de
    `voice-preferences.ts`/`screenshare-preferences.ts`:
    ```ts
    export type ParticipantAudioPreference = {
      /** 0..2 — 1 é o volume normal; 2 é o dobro, como o Discord permite. */
      volume: number
      /** Silenciado só para mim. Diferente de mute do participante (que é dele) e de ensurdecer (que é tudo). */
      silenced: boolean
    }
    export type ParticipantVolumes = Record<string, ParticipantAudioPreference> // chave = identity do LiveKit = users._id
    ```
    - `STORAGE_KEY = 'janja:participant-volumes'`.
    - `loadParticipantVolumes()`, `saveParticipantVolumes(map)`, ambos
      tolerantes a storage ausente e a JSON corrompido (o ambiente de teste
      padrão do projeto não tem `localStorage`, o que torna esse caminho o
      estado nativo do teste).
    - `sanitize`: descartar chaves cujo valor não seja objeto; `volume`
      fora de 0..2 é grampeado (`Math.min(2, Math.max(0, v))`); `silenced`
      não-booleano vira `false`.
    - Higiene de tamanho: podar entradas em volume 1 e não silenciadas ao
      salvar — guardar o padrão para 200 pessoas é lixo que cresce sozinho.
    - **A regra central, pura e testável:**
      ```ts
      export function effectiveVolume(
        pref: ParticipantAudioPreference | undefined,
        deafened: boolean
      ): number
      ```
      `deafened → 0` (ensurdecer ganha de tudo); `pref?.silenced → 0`;
      senão `pref?.volume ?? 1`. Esta função é a única fonte da verdade do
      que vai para `setVolume`, e é o que impede o conflito descrito no
      contexto.

    Teste: round-trip; storage ausente; JSON corrompido; volume acima de 2 e
    negativo (grampeados); poda do padrão ao salvar; e a tabela de
    `effectiveVolume` (ensurdecido + volume 2 → 0; silenciado → 0; sem
    preferência → 1).
  </action>
